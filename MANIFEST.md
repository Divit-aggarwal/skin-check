### SURPRISE — `lib/auth-context.tsx` was not on anyone's mental map of this cluster

`app/layout.tsx` (root layout, a required Next.js file and a given entry point)
wraps its children in `<AuthProvider>` (`app/layout.tsx:3,66`), imported from
`@/lib/auth-context`. This file is **not** in the Phase 2 excluded set by name —
only `lib/firebase.ts`, `lib/firebase-admin.ts`, and `lib/auth-cookie.ts` are named
— so per the trace rule it was copied rather than dropped. It is genuinely reached
by the transitive closure, and nothing in the skin-check/echo component tree
actually *uses* the auth state it provides (`SkinCheckFlow`, `EchoPage`, etc. never
call `useAuth`) — it's pulled in purely because the root layout wraps everything in
it. See SEVERANCE 1-3 below for what this costs.

### Note — `types/assessment.ts` is legacy scaffolding for a dead code path

`lib/gemini.ts` was copied whole per Phase 3 instructions, including its unused
`analyzeSkinImage`/`computeSkinAssessment` exports (the old `/assessment` flow's
Gemini vision + synthesis calls — not called anywhere in the live `/skin-check`
flow, whose scoring is local/deterministic via `lib/skin-check-score.ts`). Those
dead exports are typed against `QuizAnswers` (`types/gemini.ts`), which itself
imports the entire old assessment quiz schema from `types/assessment.ts`
(`ConcernSchema`, `SymptomSchema`, etc. — 5 quiz cards' worth of Zod enums, none of
which the `/skin-check` flow uses). This file is dead weight dragged in solely to
keep `lib/gemini.ts` compiling as one whole, unedited file, per the explicit Phase 3
instruction not to edit it.
